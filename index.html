Email Job Scheduler

A full-stack email scheduler and dashboard. You write a campaign, choose when it should go out, and the system sends it from several sender mailboxes while respecting each sender's rate limits.

The hard part was reliability: there is no cron, nothing important lives in memory, and an email is never sent twice, even if the servers crash halfway through a campaign.

Open live app Live API docs The live app uses Google sign-in. Source is in a private repository; happy to walk through it in an interview.
exactly-once

Never sends the same email twice

An atomic claim lets only one worker move an email to "sending". In a test, 25 simultaneous claims produce exactly one winner. Requests carry an Idempotency-Key, so a double-click can't create a second campaign.

0 cron jobs

Scheduling on delayed jobs

Every email is a BullMQ delayed job. Redis writes them to disk, so due times survive a Redis restart.

any number of workers

Rate limits that hold across machines

One atomic Lua script in Redis enforces per-sender spacing and hourly caps. Emails over the limit move to the next hour, in order, and none are dropped.

restart-safe

Nothing lives only in memory

Graceful shutdown finishes the sends already in flight. On startup, a reconciliation step recreates any lost jobs. A crash mid-send is flagged rather than retried blindly.

1,000 emails · 251 ms

Measured under load

A load test schedules 1,000 emails due in the same minute. The SMTP server received exactly the expected messages, and every sent email shows one attempt.

218 unit + 117 integration

Tested against real services

The integration tests run against real MySQL, Redis and Elasticsearch, covering crash recovery and concurrent workers. GitHub Actions runs everything on every push.

Also: Slack OAuth alerts when a sender hits its hourly limit (webhooks encrypted with AES-256-GCM, one alert per sender per hour) · Elasticsearch search with zero-downtime reindexing · Google sign-in · OpenAPI docs generated from the validation schemas · Dockerized and deployed on Railway and Vercel.
